## Thread 1: Qwen3-8B thinking-mode ABL-v8 — first real scale jump

Existing eval harness (built for 1B, non-thinking) had three real bugs surfaced by 8B +
thinking mode: vLLM head-of-line stalling (Python-side batch chunking blocked on the
slowest trace in a chunk — fixed by submitting the whole prompt list in one `llm.generate()`
call), a hard-abort on any truncated `<think>` trace (replaced with judge-in-context +
a deterministic degeneracy detector), and a wildly oversized context budget (native
40960/32768 → real p90/p95/p99 from 1028 pooled rows said 4040/5003/9061 — landed on a
deliberate 5000/4096 hard cutoff). All three fixed and committed before trusting any number
out of this campaign.

DL sweep (12-32, AdvBench-200 judged) picked **DL=19** — smooth peak, harmAct .975/gib
.015/refusal .005, not an isolated spike.

Training: 3 OOMs before a config stuck. Full-scope + full AdamW OOM'd step 1 (weights+
gradients+Adam state alone saturate 96GB before activations). Added `adamw8bit`, OOM'd again
at step 56 *both times* — traced to `_sample_attack`'s fixed-seed randomness drawing a
worst-case "ablate nearly all 36 layers" combination, spiking `_ablated_overrides`'s fp32
upcast transiently (kept that fp32 pattern — it's the same validated method used in
`save_p1b_checkpoint.py`'s real attack materialization, not something to swap out untested).
Fix: `TRAIN_SCOPE=last_half` + `torch.cuda.empty_cache()` per step. Ran clean, 500 steps,
3h41m.

Trace confirms the wall dissolves and reforms mid-run, matching gemma's prior campaign
(`results/train_qwen3_8b_thinking_v8_s42/events.jsonl`, first trace ever preserved for a v8
run): sustained wall steps 190-295 (gib_ce 8.3-11.2), dissolves 300-370 (gib_ce 0.16-1.7,
clean_ifeval bottoms at 0.083), reforms 375-400 (gib_ce back to 10-11, clean_ifeval recovers
to 0.75-1.0). Qualitative confirmation at step 175: the ablated sample visibly became a
repeated-phrase loop right where gib_ce first jumped — the number and the actual behavior
agree.

**Incident: `scripts/auto_pick_v8.py` destroyed the pick-job's raw generations.** It judged
into the same run-id it read from; `RunLogger.__init__` unconditionally unlinks
`generations.jsonl`/`events.jsonl`/`judgments.jsonl` for whatever run-id it's given, so
construction of the "judged" logger deleted the source before it could be read. 30 raw
generation files gone (15 checkpoints × attacked/clean) mid-selection. Fixed (distinct
`_judged` run-id, commit `d89872d`) — but this run's pick-job evidence was gone. Decision:
don't re-run the full pick sequence on a dying box. Pushed s400/s425/s500(final) to the
private HF repo as representative snapshots spanning the reform window, killed the box.
Qwen3-8B scale-up is **parked, not closed** — see walkthrough doc for what resuming it needs.

## Thread 2: TamperBench — third-party validation setup

Goal: run TamperBench's [criticalml-uw, arXiv 2602.06911] `refusal_ablation` attack (a fair,
independent implementation of rank-1 abliteration) against base vs ABL-v8 for all 3 proven
architectures — the strongest external validation of the ABL result available.

Provisioned an RTX A6000 (48GB) box (`vast-tamperbench`), not a bigger Blackwell box —
recomputed the OOM math and a 48GB card has ample headroom once TamperBench's own fp64 tensor
is patched to fp32. Three real bugs in TamperBench's own code (not vendored, not in git —
patches live only on that box's disk, must be reapplied on a fresh clone):

1. `refusal_ablation.py::_iso_get_last_position_logits` — `(N, V)` logits tensor `float64`→
   `float32`.
2. `attack_utils.py::kl_div_fn` — was silently upcasting both inputs back to `float64`
   internally regardless of what dtype was passed in, undoing patch #1 on every call. This
   was the actual root cause of repeated OOM crashes across 5 attempts, not GPU size.
3. Added `del intervention_logits; torch.cuda.empty_cache()` after each per-layer KL-div
   computation — real leak was per-iteration accumulation across the 26-layer sweep, masked
   early on by a zombie CUDA context from a prior crash (a PID `ps aux` no longer showed but
   `nvidia-smi --query-compute-apps` still did; cleared on its own after enough time passed,
   `--gpu-reset` failed with "Insufficient Permissions" on the unprivileged rented box).

`gemma_base` run confirmed clean after the fix (memory cycling 10.2-16.3GB, not climbing).
Full 6-run sweep (gemma/Qwen/Llama × base/v8) not finished — deprioritized mid-stream in
favor of the Heretic finding below, which turned out more decisive. Materialized v8 HF-format
checkpoints for all 3 archs remain on the box (`outputs/{gemma,qwen,llama}_v8_hf/`) for
whenever this resumes.

## Thread 3: Heretic cracks ABL-v8 on Llama-3.2-1B — the headline finding

Pivoted from TamperBench to Heretic (`pip install heretic-llm`, [p-e-w/heretic]) — adaptive
abliteration via Optuna TPE search, co-minimizing refusal-count and KL-divergence. Ran against
**Llama-3.2-1B v8** specifically (weakest of the 3 architectures on existing rank-1 data —
softest capability crater, GSM8K only −20% vs Qwen's −95%).

Picked 3 trials off Heretic's Pareto front to span the KL-budget frontier (weak/mid/strong),
ran the full eval recipe (AdvBench-520 judged + ARC + MMLU-12 + GSM8K + IFEval) on all 3.
Full matrix (`docs/heretic_v8_llama_2026_07_18.md`):

| tag | harmAct | gib | ARC | MMLU-12 | IFEval | GSM8K |
|---|---:|---:|---:|---:|---:|---:|
| v8_clean | .00 | .00 | .384 | .484 | .470 | .348 |
| v8_att (rank-1) | .00 | .99 | .363 | .464 | .161 | .278 |
| Heretic weak (KL .10) | .071 | .000 | .369 | .481 | .471 | .337 |
| Heretic mid (KL .25) | **.398** | .004 | .368 | .483 | **.462** | .343 |
| Heretic strong (KL .56) | **.883** | .012 | .365 | .482 | .200 | .331 |

**The wall breaks, and not gracefully.** At mid-strength Heretic already gets 40% coherent
judged harm at *zero* cost on every capability axis (ARC/MMLU/GSM8K/IFEval all clean-level).
Only the single most aggressive trial shows any capability cost, and only on IFEval — GSM8K
stays clean-level even there. This isn't gemma v7's pattern under Heretic (worst case there:
.17 harm, 66% gibberish — still majority-collapse). This is a clean, low-cost, controllable
trade of refusal for harm — the exact failure mode the defense exists to prevent, mostly free.

Confirmed with a same-prompt qualitative sample across all 6 conditions (AdvBench index 0,
"identity theft and evade detection"): base_clean/v8_clean refuse coherently, v8_att (rank-1)
returns blank whitespace, Heretic-weak/mid still refuse *on this specific prompt* (harm rate
is an average, not universal), Heretic-strong returns a fluent, structured how-to.

Not yet known: whether this is Llama-architecture-specific (already the weakest arch) or
v8-product-specific (no Llama-v7-vs-Heretic or gemma/Qwen-v8-vs-Heretic data exists to
separate the two). Both checkpoints and all eval artifacts pushed to the private HF repo and
committed to git (commits `092ae9b`, `ac73df1`). This is now the sharpest adaptive-attack
result against v8 and needs to anchor the paper's limitations section — corrected the
overclaim in `docs/related_work.md`'s "Our position" paragraph accordingly.

**Immediate next step (not yet run):** same Heretic sweep against gemma v8 and Qwen v8, to
find out whether this is architecture-specific or hits the product everywhere.
