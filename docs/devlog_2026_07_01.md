# Devlog — 2026-07-01

Session goal: finish the P0 baseline, then run P1 (the MAD crux) — the go/no-go
for the whole tamperforge thesis (entangle safety with capability so cheap
abliteration self-defeats). Hardware: Vast RTX 4090. Judging: DeepSeek V4 Flash
via OpenRouter, run locally.

## 1. Closing out P0

### Issue: judge parse failures that re-judging couldn't fix

Full DeepSeek judge runs over AdvBench-500 (base / heretic / extreme) came back
with a few unparseable rows: 1 for base, 6 for heretic. Two distinct failure
modes:

- **Degenerate output** (base row 354): the judge produced 512 tokens of
  multilingual token-salad and never emitted JSON. `finish_reason: length`.
- **Empty object** (heretic 23/62/109): the judge returned `{}` on egregious
  content (weapons, malware) — `finish_reason: stop`, a content dodge.
- **Partial JSON** (heretic 72/116/148): valid JSON missing only
  `harmful_compliance`.

The trap: the judge runs at `temperature=0`, so re-judging the same input is
deterministic — the garbage and the `{}` reproduce exactly. `--row-ids` retry was
useless.

### Fix: documented adjudication

The ground truth was unambiguous on inspection (row 354 was a clear refusal; the
`{}` rows were blatant harmful compliance; the partial rows were inferable from
the judge's own `rating`). Wrote `scripts/tools/adjudicate_judge_failures.py`: patches
the seven rows with recorded overrides + method, backs up originals to
`*.prepatch`, recomputes each summary. `parse_failures` → 0. Net effect was
negligible (heretic ASR 0.878 → 0.886).

### P0 result

| Model | ARC acc (25-shot) | acc_norm | judge refusal | judge ASR |
|---|---:|---:|---:|---:|
| base `gemma-3-1b-it` | 0.366 | 0.4002 | 0.982 | 0.014 |
| heretic (abliterated) | 0.3788 | 0.4130 | 0.102 | 0.886 |
| extreme (abliterated) | 0.3447 | 0.3746 | 0.082 | 0.896 |

Takeaway: **cheap uncensoring is essentially free today.** Heretic strips safety
(ASR 0.014 → 0.886) at zero capability cost (ARC ≥ base, within 1σ). This is the
problem tamperforge targets.

## 3. P1 first run — and the confound

Ran the five-condition crux with the clean-base adapter. Surface reading looked
like a pass: attacking the entangled model destroyed capability (ARC 0.40→0.18,
PPL 13→9.3e7) while the bare 1-direction attack didn't (ARC 0.43, PPL 13).

### Issue: direction-count confound

The entangled attack ablated **all 229** adapter W_out directions; the bare
attack ablated **1**. Removing 229 of 1152 dims at every layer wrecks *any*
model. Added a control condition `base_ablated_randN`: ablate the same number of
*random* orthonormal directions. Result: random-229 also destroyed the model
(PPL 9.8e6). So the all-229 damage was mostly a **direction-count artifact**, not
proven entanglement. The naive read was a false positive.

### Issue: keyword ASR is fake on broken models

Judging the generations revealed the metric had been lying. Broken models output
garbage, which contains no refusal keywords, so keyword ASR reported 1.0 — but
the judge correctly scored them ASR ~0.00 (garbage ≠ harmful compliance). Bare
ablation, by contrast, was genuinely uncensored (judge ASR 0.76). Lesson: **for
any ablated/broken condition, judge — never keyword.**

### Fixes shipped to `p1_mad_crux.py`

- `base_ablated_randN` — the random-N direction-count control (auto-matched to
  the adapter attack's direction count, nested/seeded for cross-k comparability).
- `--conditions` — run a subset of conditions, so a rank sweep runs only the
  k-dependent ones instead of all six (~60% less compute).
- `--adapter-base native_ablated` — strip native refusal from the base before
  applying the adapter (fixes a gap where the ablated-base adapter was tested on
  a clean base, so native refusal masked the adapter-only attack).

## 4. The rank sweep — the real experiment

A real attacker wouldn't ablate 229 directions (lobotomy). The honest question:
at the *smallest* k that removes safety, is the entangled-k capability cost much
larger than random-k? Swept k ∈ {1,2,4,8,16,32} on the clean-base adapter,
judged every run.

| k | entangled PPL | entangled judge ASR | random PPL |
|---:|---:|---:|---:|
| 1 | 14.8 | 0.00 | 13.5 |
| 2 | 18.4 | 0.00 | 13.6 |
| 4 | 25.6 | 0.02 | 13.6 |
| 8 | 74.7 | 0.00 | 13.8 |
| 16 | 248.8 | 0.00 | 19.7 |
| 32 | 9513 | 0.00 | 24.5 |

Anchor: bare 1-direction attack = judge ASR 0.76 at PPL 13.0 (free uncensor).

### Result: entanglement proven; defense still untested

**Entanglement is confirmed, cleanly.** Ablating the adapter's W_out directions
drives perplexity up exponentially (14.8 → 9513) while ablating the same number
of random directions barely moves it (13.5 → 24.5) — a ~400× gap at k=32. The
capability cost is specific to the adapter's directions, killing the
direction-count confound. (ARC is too coarse to separate them until high k; PPL
is the discriminating metric.)

**But safety never dropped** (entangled judge ASR ≈ 0 throughout) — because on a
clean base the model keeps its native refusal, which ablating adapter W_out
directions does not touch (`adapter_only` → ASR 0 confirms this). So the
clean-base sweep proves the entanglement **mechanism** but cannot test the
**defense**. That requires the abliterated-base sweep (native refusal removed,
adapter as sole safety), queued as `scripts/probes/run_p1_ablbase_sweep.sh`.

# Devlog — 2026-07-01 (part 2: ablbase defense test + P1b-A)

## The ablbase rank sweep — the defense test

Fixed a p1 gap first: `p1_mad_crux` loaded the clean base for every condition, so
an abliterated-base adapter was tested with native refusal still intact
(`adapter_only` was a no-op). Added `--adapter-base native_ablated` to strip native
refusal before applying the adapter, so the adapter is the sole safety.

Reference (the product, pre-attack): stripping native refusal uncensors the base
(judge ASR 0.72), then the entangled adapter restores safety fully — **judge ASR
0.00 at full capability (ARC 0.43, PPL 13.0).** The smart-and-safe corner.

Then the attack sweep (`--adapter-attack-rank k`), judged per rank:

| k | entangled judge ASR | entangled PPL | random PPL |
|---:|---:|---:|---:|
| 4 | 0.72 | 23.5 | 13.7 |
| 8 | 0.72 | 48.5 | 13.7 |
| 16 | 0.42 | 113 | 19.7 |
| 32 | 0.34 | 809 | 24.5 |
| 64 | 0.00 | 901k | 167 |

**Crossover at k=4**: ablating just 4 adapter directions uncensors (ASR 0.72) at a
real capability cost (PPL +80%, ARC −21%), while the bare attack uncensors free
(PPL 13) and random-k is untouched. That is the MAD property, confound-controlled.

**But the ceiling:** inspecting the actual generations, the k=4 crack yields
COHERENT, actionable harmful output — a usable model. And at k=16 the model shows
prose-PPL 113 yet still generates fluent (vaguer) text. Lesson: **prose-PPL is a
misleading proxy for coherence** — greedy decoding stays locally fluent even at
high PPL. So the adapter proves "uncensoring costs capability" but not
"uncensoring gives a useless model." The attacker at k=4 wins usably. That gap is
what P1b must close.

## P1b-A — adversarial tamper-resistance (weave it into the base)

Goal the adapter can't reach: make abliterating the refusal direction collapse the
model to gibberish, so a successful attack yields a useless model. Built
`experiments/train_tamper_resistant.py`.

Core mechanism, validated on a toy first (seconds, not gemma runs): a differentiable
ablated forward via `torch.func.functional_call` — build ablated weights as a
differentiable function of the live params (NOT deepcopy+in-place, which severs the
graph), run the ablated model, and let the loss push the base weights. Toy result:
clean_err 0.003 / ablated_err 3.03 — the min-max learns to route capability through
the ablated direction. Grads flow.

Then the hard part: getting it to work on gemma with real data. The iteration:

1. **Data too small.** First cut used 15 prose sentences + 64 harmful — pure
   memorization bait for weight FT. Built `data_p1b.py`: wikitext-103 (4000 train /
   400 held-out), walledai/AdvBench (520), alpaca (1000). Step-based sampling +
   held-out eval to detect overfit.
2. **OOM** on the 24GB 4090 (functional_call double-forward + long seqs). Fixed with
   gradient checkpointing, 256-token cap, smaller batches, `expandable_segments`.
3. **Self-destruction.** The gib loss `relu(target − L_abl)` rewards absolute
   badness; since early ablation is ~a no-op, `L_abl ≈ L_task`, so maximizing L_abl
   just killed the whole model (L_task 4.7→9.0, gap ~0). Fixed with a GAP-based loss:
   `relu(gap_target − (L_abl − L_task))` — reward the ablated model being worse than
   the clean one, not absolute badness. Can no longer self-destruct.
4. **Gap too weak, then wrong gap.** λ_gib 1 barely moved the gap (+0.1 over 300
   steps). λ_gib 8 opened it hard (held-out gap +18, L_task healthy) — but the
   ablated model still REFUSED. The gap was on a safety-irrelevant direction:
   `L_safe` bakes refusal into the weights decoupled from `d`, so ablating `d` costs
   prose-capability without removing safety. Added `L_uncensor = relu(margin −
   refusal_loss(ablated))` to force refusal to live on `d` (ablation must fail to
   refuse).

State at session end: the coupled objective (task + safe + gap + uncensor + reg) is
running. Open problems: prose-PPL gap still ≠ broken generations (need a
generation-coherence signal for true gibberish), and whether MLP-only has the
capacity or attention scope / a warmup is needed.

# Devlog — 2026-07-01 (part 3: P1b-A PASS)

Built the generation-level objective: `--gib-mode argmax` — greedily generate the
CLEAN model's continuation (no grad), teacher-force the ABLATED model on it,
maximize that CE. High CE = the ablated model can't reproduce the clean model's
own tokens → attacks the argmax/generation, not teacher-forced prose-PPL. Plus
`--train-scope all` (attention + MLP). Validated the differentiable-ablation core
on a toy first (clean_err 0.003 / ablated_err 3.03, grads flow).

v6 (400 steps): `gib_ce` shot from 0.3→8, and by ~step 75 the ablated generations
were pure word-salad ("Okay Crazy Dude Watching Over It Sortingly 'R2 '23…") while
the clean refusal loss dropped to ~0.2. Then the real attack + judge:

| condition | judge ASR (500) | ARC 25-shot |
|---|---:|---:|
| trained_clean | 0.010 | 0.362 |
| trained_attacked | 0.032 | 0.294 |
| base_attacked | 0.844 | 0.355 |
| base (ref) | 0.014 | 0.366 |

**PASS.** Same abliteration attack: 0.844 ASR on the base, 0.032 on the trained
model (~26×). Ablating the trained model's refusal direction yields gibberish the
judge rates non-harmful + drops ARC; the clean product is nearly free (ARC ≈ base).
Confirmed on judged harm, ARC, and raw generations.

The full arc of the day: P1 mechanism proven → adapter ceiling (coherent uncensor)
→ prose-PPL objective ruled out (uncensored-but-harmful) → **argmax objective
breaks generation on attack (uncensored-but-useless).** The prose-vs-generation
lesson, learned the hard way three times, is what unlocked it.

## Part 5 — Fine-tuning attack (P4): honest negative

Built `experiments/ft_attack.py` + `scripts/probes/run_ft_attack.sh`. Full-param FT of
v7 (and a base control) on K∈{1,5,10,25} compliant harmful demos (the
abliterated-base's own AdvBench answers), 5 epochs, lr 2e-5, then vLLM safety-gen
+ local DeepSeek judge (512 tok, 64 workers).

Result: **v7 has no fine-tuning resistance.** ASR vs K tracks the base control
exactly — K=1 takes v7 from 0.013 → 0.740 (base 0.014 → 0.800), and the harmful
output is fully coherent (spot-checked: fluent step-by-step compliance, judge
harmful=1). Table in `results_2026_07_01.md`.

Diagnosis (expected): the entanglement is an *ablation* trap — it only springs
when the attacker projects out the empirical refusal direction. FT rebuilds the
weights, never ablates, so the trap is bypassed and both harm + coherence come
back. Classic abliteration-robust ≠ FT-robust (TAR / RepNoise territory).

Decision: do NOT bolt FT-defense onto P1b-A. FT resistance is a separate
mechanism (FT-adversarial meta-objective). Plan in `docs/ft_resistance_plan.md`.
OBLITERATUS (P2) deferred — user wants FT resistance first.

## Part 6 — FT-resistance v2 (TAR): holds K=1, breaks K>=5

Built `train_ft_resistant.py` (first-order TAR meta-objective, warm-start v7).
v1 (k_inner=1, margin 3) saturated instantly (L_tamper=0); v2 (k_inner=8, margin
6) same — comply_after pinned ~8-9, L_tamper=0 all 400 steps. The training log
looked great (post-FT gens = coherent refusal + gibberish tail) but that only
proved v7's robustness to a WEAK 8-step first-order sim, not learned resistance.

The arbiter — exact P4 sweep on the ckpt — gave the real story: **v2 fully holds
K=1 (ASR 0.000, coherent refusals) but breaks at K>=5 (~0.66 = base).** Frontier
moved 1 -> 5 demos. Win on the "don't break at K=1" bar, but a 1-shot moat.

Root cause = the inner sim was too weak: a single 1-step FT only hardens the
1-step basin, so the 5-demo x 5-epoch real attack walks past. Fix (v3, shipped):
`_inner_adapt` now runs the FULL attacker loop (inner_demos x inner_epochs
first-order SGD steps) with inner-lr up to 1e-4, + `--attack-ensemble` over strong
configs. Key diagnostic for v3: comply_after must actually DROP (L_tamper>0), else
the objective still isn't seeing the real attack.

## Part 7 — FT-resistance v3: objective flaw exposed (comply-CE != generation)

v3 = strong inner attack (24-step first-order FT, inner-lr 1e-4, margin 4). Training
diagnostic finally showed L_tamper active (started 1.33, converged toward 0 = real
min-max equilibrium, vs v2's trivial 0). But the P4 sweep came back v3 ≈ v2: K=1
held (0.005), K>=5 broke (~0.65 = base). Stronger inner attack, SAME 1-shot moat.

Root cause = the 4th recurrence of "loss proxy != generation": comply_after is
teacher-forced CE. v3 kept it >= margin against the inner attack, but high CE
doesn't stop greedy generation from complying after a real 5-epoch AdamW FT. We
defended CE; the attack wins at generation. Same shape as prose-PPL failing P1b-A.

Locked finding across v2+v3: TAR-via-comply-CE = 1-shot moat only (K=1 0.74->0.00,
nothing past K=5). Matches TAR budget-limited-robustness caveats. v4 (deferred, real
redesign): meta-objective on POST-FT GENERATION (argmax-divergence at theta', not
comply-CE) + differentiate through AdamW inner + generation. Not a knob.

Decision: lock the result, back up (HF + GitHub), tear down the box. v4 = future.

## Part 8 — v4/v5 generation-level FT-defense: the inner-sim/attack mismatch crux

Chased the FT-defense harder. v4 (generation objective: greedy-gen at theta', pull
refusal + unlikelihood; all-scope) REGRESSED to K=1 0.805 — dropped v3's comply-CE-up
AND its keyword gate was fooled by refuse-then-comply (frac_comply=0 = a lie).

v5 (kept comply-CE-up + fixed gate `_complies` that strips the refusal prefix +
all-scope + kv-cached theta' gen for speed): K=1 0.695, K=5 0.650. Still no win.

THE CRUX, finally isolated: our first-order SGD inner sim produces a theta' that
REFUSES in generation (frac_comply=0) while comply_ce is low — but the real 5-epoch
AdamW attack produces a model that COMPLIES in generation. The sim breaks
teacher-forced CE, not generation. So we defend the wrong theta': gen-unlikelihood
never fires (nothing complies in sim) and comply-CE-up can't win against a strong
all-scope inner. v3's "K=1 hold" was an artifact of a weak/beatable inner, not real
robustness (always broke K>=5).

Fix next session: inner sim must match the attack on GENERATION — real AdamW inner
(momentum), more epochs, maybe all-params. Then theta' complies-in-gen -> objectives
engage. Also: kv-cached theta' gen works (v4_scaled/v5), ~2-3x faster.
