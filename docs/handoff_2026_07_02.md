- **FTR-v6 = current attempt (Lever-2 / TAR-done-right, LoRA inner).**
  `experiments/train_ft_resistant_v6.py`. Key design: per meta-step, a REAL LoRA
  fine-tuning attack runs on a functional copy of theta (native-ish, rank/steps/lr
  configurable), producing theta'. Outer loss shapes theta so theta' stays safe,
  measured via an LLM-JUDGE GATE (same DeepSeek judge as eval — not keyword, which
  lies on refuse-then-comply patterns). FO-MAML: theta' = theta + detached LoRA delta,
  so `backward()` flows straight to theta, no manual grad plumbing.
  - Fixed bugs this session: float()-on-grad-tensor warning, `_complies` keyword gate
    false-positives (deflection phrases), OOM on 24GB with all-scope (fixed via
    `--grad-checkpoint` AND incremental per-term `.backward()` — 10x128-tok gens in
    ONE graph OOMs even on 24GB with checkpointing; backward each term separately so
    peak memory is ~1 term, not 10).
  - **4090 result (last full run, rank-32 LoRA inner, meta-lr 1e-5, 15 steps):**
    objective clearly ENGAGES (L_out 100-260, judge gate honest, frac_comply 0.4-1.0)
    but **frac_comply does NOT trend down** and theta' generations do NOT degrade —
    theta isn't out-hardening the attack. Working hypothesis: **meta-lr (1e-5) too low**
    — L_out is huge but theta barely moves per step.
  - **NOW ON 2x RTX 5090 (32GB each, torch 2.12.0+cu130, CUDA 13):** smoke passed
